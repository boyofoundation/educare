# 計畫一：UI／UX 改善

狀態：U1–U6 工程整合與自動化驗證已完成，尚未完成全部驗收。2026-09-20：1,489 項單元測試、15 項 headless production E2E、typecheck、lint、build 通過；LCP 中位數由 4,744 ms 降至 3,668 ms，仍未達 2,500 ms。真人試用、實機鍵盤／旋轉、VoiceOver 與完整 200% 縮放／對比檢查仍待驗收；Canvas 選檔／checkpoint 後的完整行動瀏覽器情境亦未覆蓋。詳細結果、profile 與限制見[驗證紀錄](./2026-09-20-uiux-validation.md)。優先於功能擴充；本次未開始後續功能波次、未部署。本計畫以繁中、老師備課與學生使用情境為預設，不新增後端。

## 目標與範圍

讓使用者知道「現在在哪裡、下一步做什麼、資料有沒有存好、為何不能操作」。沿用現有模板、聊天虛擬化、停止／續跑、語音與 Canvas，先修復可驗證的互動阻礙，再調整視覺。預期效果為待驗證假設，不宣稱目前已有完成率／滿意度數據。

建議資訊架構：主導覽保留「助理／聊天／教材與作品／設定」，依工作情境顯示次層；新手建立採「選用途與模板 → 確認名稱 → 開始使用」。模型、系統提示、子代理與 HTML 設定放進可展開的進階區。這是 UI 分組，不是新增帳號或教師／學生權限系統。

## U1｜首次使用與漸進設定（P0，3–4 日）

**依據：** `components/core/AppContext.tsx:315` 無助理時進編輯頁；`components/assistant/AssistantEditor.tsx:220` 起呈現完整表單；AI 設定入口在 `components/core/AppShell.tsx:415`。已有 `TemplateSelector`、`WelcomeMessage` starter prompts，可直接沿用。

**實作順序：**

1. 在 `AppShell.tsx`／`AppContext.tsx` 新增可跳過的首次使用導覽，提供「套用模板」「匯入助理／協作包」「先瀏覽」；完成狀態本機保存，可從設定重開。
2. 精簡 `AssistantEditor.tsx` 初始區塊為名稱、用途／描述、模板；保留進階欄位與舊資料，套模板前若會蓋掉編輯內容則顯示差異／取消入口。
3. 未設定 AI 時，在聊天輸入旁呈現原因與直接設定入口；完成設定返回原助理和草稿。模型設定先顯示一個選中的供應商，再展開其他選項。

**驗收：**

- 乾淨儲存且無 API key，可完成模板建立、檔案匯入及瀏覽已存內容，不要求先設定 Turso。
- 從選定模板到進入聊天最多 3 個主要操作，不必編輯系統提示；提供 mock AI 的 E2E，驗證設定後可發第一則訊息。
- 跳過／完成導覽後重載不重複阻擋；舊使用者、分享網址、協作包深連結維持原入口。
- 邀請 5 位未接觸專案的目標使用者做「建立英文助理」試用，至少 4 位不需口頭提示完成；未試用前不得宣稱目標達成。

**風險：** 簡化可能藏住教師常用設定；進階區保留直接入口與選擇記憶。供應商直連／key 限制遵守 F2，不包裝成匿名免費 AI。

## U2｜鍵盤、無障礙與錯誤回饋（P0，3–4 日）

**依據：** `components/core/Layout.tsx:338` 關閉側欄僅做 translate；`components/ui/Modal.tsx:13` 只有 Escape／捲動處理；`:56` 使用固定標題 ID。`index.html:2` 是英文語言；`AssistantEditor.tsx:147`、`ProviderSettings.tsx:167` 使用 alert。

**實作順序：**

1. 將頁面語言與主要文案統一為 `zh-Hant`；為英文片段保留必要語言標示，統一「儲存／匯入／協作包」用詞。
2. 關閉的手機 drawer 移出焦點順序／無障礙樹；開啟時管理焦點、背景互動、Escape 及關閉後的焦點返回。桌面 rail 保留可操作性。
3. 擴充現有 Modal：唯一 label ID、初始焦點、Tab 圈限、關閉後返回、巢狀最上層 Escape／捲動鎖；所有使用者操作皆可取消。
4. 驗證錯誤放在相關欄位旁並使用 `aria-invalid`／`aria-describedby`；成功提示用非阻斷 status。刪除維持明確確認並列出受影響資料，不在尚無還原能力時顯示「復原」。

**驗收：**

- 以 Tab／Shift+Tab 操作：關閉 drawer 不得取得焦點；開啟 modal 不能進入背景；Escape 只關最上層，焦點回觸發按鈕。
- 同時開兩個 modal 無重複 ID；最後一個關閉後頁面捲動恢復。
- 空名稱、模型連線失敗、上傳失敗均有可讀原因與重試／修正操作，非只顯示 alert 或顏色。
- 主要觸控操作目標至少 44×44 CSS px；一般文字對比以 4.5:1、主要控制邊界以 3:1 作專案驗收目標；檢查鍵盤 focus ring 與 200% 縮放。
- 擴充 `components/ui/__tests__/Modal.test.tsx`、`components/core/__tests__/Layout.test.tsx` 與表單測試；以 VoiceOver 至少走完導覽、表單、聊天，不宣稱全站已取得無障礙認證。

焦點行為依據：[W3C Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

## U3｜手機、長表單與聊天／作品切換（P1，2–4 日）

**依據：** `AssistantEditor.tsx:479` 按鈕在表單底部；`Layout.tsx:331` 使用 h-screen；`AppShell.tsx:277`／`:334` 以聊天和作品雙欄配置。B1 已量到手機保存按鈕離首屏很遠；軟鍵盤遮擋尚未實測。

**實作順序：** 長表單拆成可展開區塊並保留可見保存狀態／操作列；使用動態 viewport 高度及安全區；窄螢幕以聊天／作品切換，寬螢幕維持雙欄。保留 `ChatInput.tsx:114` 中文輸入法 Enter 保護、既有自動高度及停止按鈕。

**驗收：**

- 360、390、768、1280px 寬度，建立、編輯、模型設定、聊天、Canvas 皆無整頁水平捲動；寬表格／程式碼可在自身區域捲動。
- 表單捲動後仍可取得保存／取消，操作列不遮最後欄位；保存中重按不重複新增。
- iOS Safari／Android Chrome 實機開鍵盤後可見輸入、送出／停止；旋轉、關鍵盤不遺失內容。模擬 viewport 通過不能取代此項。
- 開關 Canvas、選取檔案或恢復 checkpoint 後，對話捲動位置與作品內容保持；新增 `tests/e2e/` 行動情境。

**風險：** 固定操作列可能遮住內容，預留底部空間並測試縮放／安全區；Canvas 與聊天各自保留焦點與捲動，不新增行動版獨立資料模型。

## U4｜讓本機保存、分享、離線狀態說清楚（P1，2–3 日）

**依據：** `RAGFileUpload.tsx:74` 只更新父層，`:81` 卻說已保存；`AppShell.tsx:342` 設定頁沒有文案指向的遷移入口。分享可用性來自 `hooks/useTursoAssistantStatus.ts`，本機檔案出口已在 `Layout.tsx:427`。

**實作順序：**

1. 區分「已解析、尚未儲存」「儲存中」「已存於這台裝置」「儲存失敗」；耐久保存成功才能顯示已保存。錯誤保留表單，提供重試。
2. 分享對話框先提供「匯出檔案」，將 Turso 網址標為選用雲端功能，說明是否含教材、聊天、憑證；不要使用沒有實際入口的遷移指引。
3. 先以現有資訊呈現網路／模型設定狀態；F1 完成後接容量和備份狀態，F3 完成後才顯示「可離線開啟」。首次使用提醒瀏覽器資料不會自動跨裝置。

**驗收：** 模擬 IndexedDB 寫入失敗不顯示成功；關閉未保存編輯有離開提示；無 Turso 仍能找到匯出入口；無網路時仍可讀本機資料，雲端推論入口明示原因；不把已設定 key 視為即時連線測試成功。每個提示有正確下一步或明確限制。

**風險：** 狀態過多造成干擾；常態只顯示精簡狀態，錯誤與資料風險才展開。後續功能狀態用 F1／F3 真實結果，不能先做假成功畫面。

## U5｜助理／對話／教材查找（P2，2–3 日，不重複計 F4 服務工期）

**依據：** `components/core/Layout.tsx:622` 直接 map 會話；`components/assistant/AssistantList.tsx:126` 已有助理列表。保留目前切換方式，增加搜尋入口、最近使用、釘選、重新命名與分類的簡單操作。

**步驟：** 先定義搜尋空狀態和結果摘要；串接 F4 本機查找服務；從結果定位對話、教材引用或作品。大量資料採按需載入／現有虛擬化，不另加搜尋後端。

**驗收：** 在 100 場對話中以繁中／英文關鍵字找到指定內容，點結果定位對應訊息；無結果可清除篩選；不同助理同名聊天仍有可辨識上下文；rename／pin 重載後保留，且不改原訊息內容。共享／bundle 模式不可搜尋到其他私人資料。

**依賴與風險：** F4 負責查詢和資料欄位，U5 負責 UI；避免 UI 各自建立第二份索引或全域曝光私人資料。

## U6｜閱讀一致性與初載效能（P2，3–4 日）

**依據：** `WelcomeMessage.tsx:13`、`Modal.tsx:53`、`Layout.tsx:331` 大量硬編深色樣式；`AppShell.tsx:1` 多入口靜態 import；分析文件已記錄 build chunk，尚無首屏效能基準。

**步驟：** 先量測再修改；在 `index.css` 提取少量語意色彩／字級／間距，加入系統／亮色／深色選擇與減少動態效果；聊天以閱讀內容為主，工具活動保留可展開摘要。沿用現有虛擬化；只對量測證實的初載入口做 lazy loading，保留錯誤邊界及載入提示。

**驗收：**

- 三種主題重載後保留選擇，數學、程式碼、引用、disabled／error 狀態都可讀；閱讀字級可調且 200% 縮放仍可操作。
- production preview 在固定 Chromium 版本、390×844、4 倍 CPU、1.6Mbps／150ms RTT，以空快取量 5 次，記錄 LCP 中位數和初載 JS gzip；目標 LCP ≤2.5 秒，若基準已更快則不退步。未達標時留下 profile 與未解瓶頸，不能只以 chunk 變小結案。
- 1,000 則合成訊息連續捲動，無訊息跳失；新增訊息不強迫正在讀歷史的使用者回底部。既有 `useStickToBottom` 與 `ChatContainer` 測試維持通過。

**風險：** 大規模樣式替換回歸成本高；先入口／表單／聊天，再擴至作品區，每次保存同 viewport 比對。視覺標記整理不改業務行為，不另引入 UI framework。

## 驗證與交付

每個 U 項目獨立提交，內容附前後畫面、測試案例和限制。`pnpm run typecheck`、`pnpm run lint`、相關 Vitest 通過後，執行完整 `pnpm run test`／`pnpm run build`；格式檢查只限該次改動檔，避免混入全庫格式化。互動變更在 Playwright 以 mock provider 驗證，不依賴付費憑證。

U1–U4 完成並通過驗收後才進入功能波次。U5 依賴 F4；U6 可在查找功能穩定後進行。完成標準是所有列出的驗收有實際結果，未做的實機與試用須列為未完成；測試通過不替代人類試用。
